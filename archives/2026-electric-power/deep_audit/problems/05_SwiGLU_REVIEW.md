# 题目 05：SwiGLU——源码缺失边界与本项目经验索引

> 本题没有出现在本次公开的九题前三名源码包中，因此**不存在可逐行审核的获奖实现**。这份文件不是获奖代码分析，而是明确记录可确认的题面、资料缺口和本项目自身经验，避免后续把我们自己的版本误标成获奖设计。

## 1. 题面契约

输入 `X[...,d]`、`W1/W2[d,d]`（按 `[out_dim,in_dim]` 存储）、`b1/b2[d]`，均为 FP16；输出与X同shape/dtype。计算

```text
z1 = X * W1ᵀ + b1
z2 = X * W2ᵀ + b2
Y  = (z1 / (1 + exp(-z1))) * z2
```

`d=1..8192`，前置乘积 `M=1..1,048,576`；非32B对齐尾部也必须支持。混合误差为 `1e-3 + 1e-3*|golden|`。题面没有完整规定投影后是否必须先物化FP16，也没有完全锁死中间舍入顺序，因此参考Judge的实际数值契约要与数学题面分开核对。

## 3. 对以后比赛可复用的通用分析框架

虽然没有本题获奖代码，仍可把其他题的通用审计方法用于未来SwiGLU版本：

1. 写出线性层、SiLU和门控逐节点的dtype/舍入图；确认W转置、偏置、尾部和最终half写回。
2. 按 `M,d` 估算两次投影的必要运算和读写；对小 `M`、小 `d`、窄尾、可复用W等形状分类，而非只调统一tile。
3. 对任何候选近似先给数学适用域、误差传播和拒绝/回退策略；FP16输入不意味着中间FP16总合法。
4. Host tiling、key、SEL、kernel入口必须闭环；源码存在不表示被调用。
5. 通过同shape、同设备、同Judge重复提交判断效果，并把波动与可归因收益分开。

这是通用方法论，不是从SwiGLU获奖代码中提取的trick。
