# 十题题面与公示源码逐行审读计划

日期：2026-11-08。用户要求：结合十题 PDF、既往 SwiGLU 实验，对公示代码按题逐文件逐行审读，记录所有特殊设计、写法和编排方式。

## 范围与不可混淆的口径

- 输入题面：`problems/1.pdf` 至 `10.pdf`，只读，不修改。
- 输入源码：本目录 `extracted/` 的 27 份公示提交、271 文件、139460 文本行；原 ZIP 与解压文件只读，保持 manifest SHA-256。
- 九题有三份公示源码；第 5 题 SwiGLU 只有题面及本项目历史材料，不制造缺失的获奖源码。
- 不执行下载源码的脚本、编译、安装、NPU 任务；自写静态校验工具可运行。
- 不宣称“无遗漏/完全正确”的绝对保证；用文件、行段、状态、证据记录实际审读覆盖。
- 禁止用关键词命中、自动分段文本、函数名列表冒充人工逐行语义审读。
- 自动生成的长表必须解释生成规则、索引、容量和消费关系；不能仅因重复就跳过。完全相同文件可按 SHA-256 复用审读结果，但必须记录映射。
- 评测 Pass 和公示分数是外部记录，不是本机数值/速度验证，也不能给单个 trick 归因。
- 用户追加：每条设计必须区分题目专属、同类问题可迁移、通用编排原则；硬件/SDK绑定另列一轴。不把题目特有代数、固定shape常量、危险的私有写法统称“通用优秀trick”。

## 每题固定审读步骤

1. 逐页读完整题面，视觉核对提取可能丢失的公式/表格，建立契约。
2. 从 CMake、Host 注册/shape inference/tiling、key 声明和 kernel 入口建立真实路由；区分未派发、编译条件关闭、仅备选源码的分支。
3. 每个文件按带行号连续片段阅读全文；记录每个语义行段，不遗漏宏、内建指令、属性、pragma、常量表、别名和资源参数。
4. 对每条路径推导地址覆盖、重复数、单位/对齐、tail、UB/L1/L0/workspace 上界和事件生产消费；无法静态确定则明确写出缺口。
5. 数学重排与 FP16/FP32/高低位分解分开审查；推导可推导的结论，不把实数恒等当浮点位等价。
6. 特殊/私有 API 以当前官方文档核验；找不到契约就记为版本绑定风险，不推测合法或非法。
7. 对三个版本逐项比较设计；每个独特机制给文件/行号/作用/可能收益机制/代价/移植前提，不能由名次反推因果。
   同时填写应用范围（题目/问题族/编排）、平台版本条件、数学与实现证明状态、性能归因状态；可迁移不等于已证明优秀。
8. 完成该题所有文件的覆盖账本，再检查原源码 hash 未变；完成度不足时保持 in_progress。

- 每个文件有来源 hash、行数和审读状态；覆盖行段无空洞且不超界。
